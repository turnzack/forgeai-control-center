# PRD — Guest Chat (Product Requirements Document)

## 1. Objectif Produit
Fournir une brique logicielle Grade Gold dans le domaine **Chat & Messagerie Temps Réel** (archétype `CHAT`), utilisable immédiatement en production. Le produit adresse le problème suivant : Les clients de messagerie actuels manquent de feedback temps réel (typing indicator, read receipts), gèrent mal les conversations groupées et n'offrent pas de recherche dans l'historique des messages.

## 2. Fonctionnalités Spécifiées

### F01 — Liste de conversations triées par dernier message, avec aperçu et horodatage
- **Objectif** : Liste de conversations triées par dernier message, avec aperçu et horodatage.
- **Préconditions** : session utilisateur active (sauf endpoints publics) ; données préchargées ou fetch à la demande.
- **Scénario nominal** : l'utilisateur interagit via `ConversationList`, l'API répond en < 200ms, l'UI se met à jour optimistement.
- **Scénarios d'erreur** : toast d'erreur + retry automatique sur 500/503 ; état vide explicite si aucune donnée ; validation Zod côté client avant envoi.
- **Critères d'acceptation** :
  - Skeleton affiché pendant le chargement (< 200ms).
  - Feedback visuel immédiat (hover, focus, transition).
  - Conformité WCAG AA (contrastes, navigation clavier, ARIA).
  - Persistance D1 vérifiée par test d'intégration.

## 3. Pages de l'application
- `/`
- `/chat`
- `/chat/:conversationId`
- `/contacts`
- `/settings`

## 4. Endpoints API
- `GET /api/conversations`
- `GET /api/conversations/:id/messages?before=`
- `POST /api/conversations/:id/messages`
- `PATCH /api/messages/:id/read`
- `GET /api/messages/search?q=`
- `WS /ws/chat (typing, presence, new message)`

## 5. Store global (state shape)
```typescript
conversations[], currentConversation, messages[], typingUsers[], userPresence{}, searchQuery
```

## 6. Interfaces TypeScript principales
```typescript
Message {id, conversationId, authorId, body, type, attachments[], createdAt, readBy[], reactions{}, replyToId}, Conversation {id, type, name, avatar, participants[], lastMessage, unreadCount}, User {id, name, avatar, status, lastSeenAt}
```

## 7. Contraintes Non Fonctionnelles
- **Accessibilité** : conformité WCAG AA (navigation clavier complète, contrastes validés, ARIA approprié).
- **Sécurité** : headers CSP stricts, protection CSRF, requêtes préparées D1 contre les injections SQL, sanitisation XSS des entrées utilisateur.
- **Performance** : bundle JS < 200 KB gzip, lazy-loading des routes, cache HTTP stale-while-revalidate.
- **Observabilité** : logs structurés JSON, métriques temps-réel, Sentry pour les erreurs front.
- **Internationalisation** : interface en français par défaut, structure i18n prête (fr, en).
