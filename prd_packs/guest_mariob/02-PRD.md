# PRD — Mariob Quest (Product Requirements Document)

## 1. Objectif Produit
Fournir une brique logicielle Grade Gold dans le domaine **Jeu Vidéo & Arcade** (archétype `GAME`), utilisable immédiatement en production. Le produit adresse le problème suivant : Les jeux web actuels manquent de boucle de gameplay satisfaisante, de système de score persistant, de leaderboard compétitif et de paramétrage (difficulté, sons, contrôles) accessible aux joueurs occasionnels comme hardcore.

## 2. Fonctionnalités Spécifiées

### F01 — Canvas de jeu HTML5 avec boucle requestAnimationFrame à 60 FPS
- **Objectif** : Canvas de jeu HTML5 avec boucle requestAnimationFrame à 60 FPS.
- **Préconditions** : session utilisateur active (sauf endpoints publics) ; données préchargées ou fetch à la demande.
- **Scénario nominal** : l'utilisateur interagit via `GameCanvas`, l'API répond en < 200ms, l'UI se met à jour optimistement.
- **Scénarios d'erreur** : toast d'erreur + retry automatique sur 500/503 ; état vide explicite si aucune donnée ; validation Zod côté client avant envoi.
- **Critères d'acceptation** :
  - Skeleton affiché pendant le chargement (< 200ms).
  - Feedback visuel immédiat (hover, focus, transition).
  - Conformité WCAG AA (contrastes, navigation clavier, ARIA).
  - Persistance D1 vérifiée par test d'intégration.

## 4. Endpoints API
- `POST /api/scores`
- `GET /api/scores/leaderboard?period=&limit=`
- `GET /api/achievements`
- `POST /api/achievements/unlock`
- `GET /api/scores/me`

## 5. Store global (state shape)
```typescript
gameState{score, lives, level, combo, status}, highScore, leaderboard[], achievements[], settings{volume, music, difficulty, controls}
```

## 6. Interfaces TypeScript principales
```typescript
GameSession {id, score, level, duration, difficulty, playerId, createdAt}, Score {id, playerId, playerName, score, level, rank, period}, Achievement {id, name, description, icon, unlockedAt}, GameSettings {volume, music, sfx, difficulty, controls, colorblindMode}
```

## 7. Contraintes Non Fonctionnelles
- **Accessibilité** : conformité WCAG AA (navigation clavier complète, contrastes validés, ARIA approprié).
- **Sécurité** : headers CSP stricts, protection CSRF, requêtes préparées D1 contre les injections SQL, sanitisation XSS des entrées utilisateur.
- **Performance** : bundle JS < 200 KB gzip, lazy-loading des routes, cache HTTP stale-while-revalidate.
- **Observabilité** : logs structurés JSON, métriques temps-réel, Sentry pour les erreurs front.
- **Internationalisation** : interface en français par défaut, structure i18n prête (fr, en).
